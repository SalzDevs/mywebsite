Why this site is plain HTML and Go

No framework, no build step, no JavaScript. Just files and one small server. It loads instantly and it's easy to change.

Every post on this site is a single HTML file. The homepage is another HTML file. There is no database, no content management system, no bundler watching files.

To write a new post I make a file, link it in the index, and push. That's the whole workflow. A text editor and git.

The Go server is fifty lines and does one thing: serve the folder. On the internet it's even simpler — a static host does the same.

I've spent enough hours in build pipelines. For a personal blog, simple beats clever every time.
